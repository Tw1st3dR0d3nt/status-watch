# Security Policy

## Reporting a Vulnerability

If you discover a security vulnerability in StatusWatch, please report it privately rather than opening a public GitHub issue.

Security issues can include, but are not limited to:

* Exposure of Discord bot tokens or other credentials
* Unauthorized access to StatusWatch functionality
* Vulnerabilities that could affect Discord servers using StatusWatch
* Improper handling or exposure of sensitive information
* Other security vulnerabilities in the StatusWatch code

### How to Report

Please use GitHub's **Private Vulnerability Reporting** feature when available.

If private vulnerability reporting is unavailable, contact the project maintainer through the contact information provided on the StatusWatch GitHub profile.

**Please do not publicly disclose a security vulnerability before it has been reviewed and addressed.**

## What to Include

When reporting a vulnerability, please provide as much relevant information as possible, including:

* A description of the vulnerability
* Steps to reproduce the issue
* The potential impact
* Relevant logs, screenshots, or proof-of-concept information
* Any suggested mitigation, if known

Please avoid including real Discord bot tokens, passwords, or other sensitive credentials in a report.

## Supported Versions

The latest version of StatusWatch available in the `main` branch is the currently supported version.

Older or discontinued versions may not receive security fixes.

## Responsible Disclosure

Security researchers and users are encouraged to allow reasonable time for a vulnerability to be investigated and addressed before publicly disclosing the issue.

Thank you for helping keep StatusWatch and the communities using it secure.
